# Cognition

一个用于外化、描绘和打磨我的认知过程的 Human-AI 共思 reference 系统。

这个项目不是为了快速完成一个 skill，而是为了把我和 AI 协作中反复出现、但尚未稳定命名的思考经验，沉淀成可回看、可发展、可复用的认知资产。

skill 是这个项目的一个可能出口，但不是项目本体。

项目真正关注的是：

```text
对话中出现模糊感
-> 提炼成概念札记
-> 多个札记之间形成认知地图
-> 稳定后写成章节
-> 再封装成 skill / prompt / 方法论
```

## 这个项目是什么

这是一个用于记录和发展 Human-AI co-thinking 过程中认知经验的 reference 系统。

它记录的不是单纯结论，而是结论生成之前的认知现场：

```text
我为什么会这样想？
我为什么会觉得 AI 的某些回答不对？
我脑子里那个还没成型的判断结构是什么？
一个模糊感如何变成问题？
一个原则如何进入现实并产生约束力？
```

这些内容可能来自 AI 协作、代码设计、写作、产品判断、学习过程或自我校准。

## 为什么存在

和 AI 协作时，很多重要判断最开始并不是清晰概念，而是一些很容易丢失的信号：

```text
这个回答好像不对。
它太顺了。
这个方案看起来能跑，但我不踏实。
这个原则听起来对，但它会改变什么？
我知道这里有问题，但说不清楚。
我是不是被 AI 的流畅性带走了？
```

这些信号如果不被记录，很容易在对话结束后消失。

这个项目试图先接住它们，再慢慢把它们发展成概念、文档、方法和 skill。

## 写作原则

reference 的写作不应该从理论完整性出发，而应该从真实触发点出发。

核心原则是：

```text
先找到真实触发点，再决定文档结构。
```

更具体地说：

```text
先体验，后命名；
先现场，后结构；
先生成过程，后稳定框架。
```

不要为了体系完整性强行补概念。

一个主题是否值得单独写成 reference，不应该主要取决于它在理论地图上是否“应该有”，而应该取决于它是否在真实思考中反复出现，是否触发过明显的卡顿、不满意、负荷、未完成感或判断动作。

## 当前 references

### `implicit-cognition`

隐性认知：语言之前的判断系统。

记录那些尚未被语言、概念和结构完整接住，但已经在影响判断、表达和 AI 校准的认知信号。

### `cognitive-probes`

认知探针：不放心感如何变成问题。

记录人在 AI 输出之后，因为不确定性而临时冒出的探测性问题，以及这些问题如何指向风险、形成验证动作。

### `dimensional-thinking-load`

升维为什么会累：新判断空间需要新的认知支撑。

记录当认知探针把人从具体结果推向更抽象、更高维的判断空间时，为什么会出现负荷、模糊、难以表达和自我怀疑。

### `principle-grounding`

原则降维：抽象原则如何变成真实约束。

记录一个抽象原则如何进入当前现实，变成可观察、可检查、可复用、可优化的约束。

### `cognitive-coordinate-system`

认知坐标系统。

用于定位当前思考的对象、操作、输出形式和确定程度，是把多个概念组织成工作模型的坐标参考。

## 与 skill 的关系

`SKILL.md` 是这些思想的一个封装出口。

`references/` 是源材料，skill 应该从 references 中提炼，而不是反过来让 references 服从 skill。

更准确地说：

```text
references 负责保存和发展思想
skill 负责把稳定后的方法用于 AI 协作
```

因此，这个项目会先允许想法在 reference 中保持探索性、半成型和可修正；只有当某些概念稳定后，才适合被压缩成 skill 规则、prompt 或方法论。

## 关于名字

这个项目叫 `Cognition`。

这个名字刻意保持宽一些。它不是通用认知科学项目，而是一个个人认知系统：用来记录我的判断、卡顿、原则和思考动作如何在人和 AI 的协作中逐渐显性化。

当前仓库目录可能仍然是 `externalize-thinking-skill`，但概念上的项目名是 `Cognition`。
